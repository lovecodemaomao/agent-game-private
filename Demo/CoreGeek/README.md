# CoreGeek：任务、经济与防守策略

基于官方 Competition Demo 修改，独立位于 `Demo/CoreGeek`，不依赖、不修改本仓库模拟平台代码。Python 3.11+，仅使用标准库。

## 启动与测试

```bash
bash Demo/CoreGeek/run.sh 8081
# 或
python -B Demo/CoreGeek/main3.py 8081
python -B -m unittest discover -s Demo/CoreGeek/tests -v
```

监听 `0.0.0.0`，POST 比赛 Request JSON。输出完整的 `roleCommandMap`、`prompt`、`executeCmd`。LLM 和命令均通过判题器调用：本地代理不会直接连接模型，也不会在本机执行模型生成的命令。

## 规则来源与任务分类

已重新 fetch 并核对 `zayx1228/agent-game` 的 `main`（90ae281）以及 `Tymonxiong/Competition` 的文档；两份任务书、接口文档相同，均为2026-09-09的v1.0。三类任务并不意味着只有三道固定题：

| 类别 | 接口 | 策略 |
| --- | --- | --- |
| 推理类 | worldNews.officialNews、vendorShopList | 每日新闻分析，提取有原文依据的矿种停采日期；实际售价以本回合清单为准 |
| 长上下文类 | worldNews.folkLegends、summonTreasure | 跨天保存传闻，LLM提取宝藏坐标、回合窗口和商品名称，校验后采购和献祭 |
| 自进化类 | playerTasks、phaseTask、prompt、executeCmd、submitAnswer | 前往己方可用任务点；**先 3 轮固定探测**（只探测 `/tmp/selfEvolutionTask/`，不做从根目录的全盘递归，避免 15 秒沙盒超时），随后把探测结果汇总成信息完整的 prompt，让 LLM 直接给出可执行的 API 调用（带 `-H "X-API-Key: heritage-api-key-2024"`，失败则换参数组合重试），拿到答案即提交并保存方法 |

### 任务执行流程

开拓者的任务执行在**任务期不占每日 LLM 额度**：前 3 回合用固定命令探测任务目录（只探测 `/tmp/selfEvolutionTask/`，避免 15 秒沙盒超时），把探测结果汇总成一次信息完整的 prompt 交给 LLM 直接给出可执行命令，之后每回合把新的命令结果回灌，逐步逼近正确答案；拿到答案立刻提交，并把"命令 + 答案"按题干归一化后存成可复用 SOP（题干按"数字→#、参数→占位"比对，命中后替换旧参数重跑，参数相同才直接提交已验证答案，绝不沿用旧答案）。该流程对题型不做任何假设：不写死天气、沙盒接口地址、文件路径或某个答案格式。

需求 4 的夜间开工与上面的流程共用同一套状态机：只要**阵前（基地/炮位 10 格内）没有活着的机器人**就算夜战结束，开拓者会立刻前往任务点并继续推进已领取的任务（`collect/acceptTask/submitAnswer/executeCmd` 等官方动作都没有昼夜限制）；机器人重新靠近时判定翻回"战斗中"，先回炮位防守。

### LLM额度及回合协议

- 非任务期间，每个130回合游戏日最多发送3次prompt，按天重置；无有效结果时允许在额度内重试，不会每回合无上限重发。
- 只有Request已包含活动phaseTask且开拓者保持在对应任务点有效范围内，才发送任务求解prompt；这些调用不占每日3次额度。
- 已发送acceptTask但尚未收到phaseTask时，不假定已经进入额度豁免期。
- 每条prompt携带request_id；只处理对应待收请求的下一回合结果，新闻结果与任务答案隔离。最终提交答案的同一回合不再发送任务prompt，避免结束时额度歧义。
- 模型按JSON协议返回command或answer；command只放进Response.executeCmd，下一回合读取lastCmdResult后再分析。识别超时/退出码/截断文本并提供给模型，不会无依据编造命令结果。
- 部分答案错误时继续修正；任务消失不自动当作成功，只有刚提交且没有错误/超时/死亡/离开范围迹象时才缓存成功步骤。缓存是进程内按队伍隔离的上下文，不跨新比赛复用答案。
- 未知任务预留20回合初始预算（不超过任务超时），预设模板类任务按 5-6 回合预算；另加走位与返程余量才接取。临近回防期限退出未完成任务，保障既定夜间防守策略；无法保证所有长任务都能在白天完成。

### 宝藏

保存多天传闻。只接受有原文依据、置信度至少0.9、坐标/时间合法、物品与商店清单一致的模型推断。需要满足物品数量、金币、背包和行程要求。合法献祭失败也消耗物品，所以每个推断方案只尝试一次，成功或已空后停止。

## 经济与工事

- 三火箭、75金币开局，优先工人相邻可建位置；基地2×2，pos左上角向y-1展开。
- 只在距基地占地1格的第一圈建武器，2格的第二圈建墙；左侧基地建右半圈，右侧基地建左半圈。
- 第一天优先建设；后续最多一名非采购工人负责补墙，另一名继续挣钱。采购工人不再被卖矿/补墙反复打断。
- 采购计划跨回合绑定工人、商品、目标建筑、预期等级；检查商店到建筑再回防的完整时间。一次只安排一名采购工人。
- **武器优先，例外只有一种（用户最新口径）**：无论哪天都是**先升级武器**（为下一张武器券保留金币）；只有**前夜围墙承伤超过 80%**（整体掉血过半或多于 80%，见 `WALL_PRESSURE_RATIO`）时才降武器升级、把围墙升级券提到前面。
- **每日计划（按天配额）**：给出当天目标：
  - 第 1 天：建完迎敌半圈围墙（10 段，石头建造）+ 两个武器升级
  - 第 2 天：4 个前挡围墙升级 + 一个武器升 2 级
  - 第 3 天：4 个前挡升 2 级 + 两个武器升 2 级
  - 平时围墙券只吃「超出武器券预算」的闲钱；仅当**前夜围墙承伤超过 80%** 时才转为围墙券先行（此时不再为武器券预留金币）。
- **修复包只用闲钱**：只有当天围墙/武器升级配额都完成后，剩余金币才用于常备 2-3 个 `WallFixer`。
- **回家前清钱**：当天最后阶段（剩余回合刚好够"去商店→购买→回位"时）优先把手上闲钱花掉——30 金买一张围墙券+一个修复包、20 金买一张围墙券、10 金买一个修复包（有 100 金则优先武器券）。
- **回位死线**：回防预算截止当天第 75 回合（入夜后的第 5 回合）；一般行动另留 2 回合余量，采购/采矿完整行程留 5 回合余量。白天在第 70 回合结束，夜间允许移动。
- **夜间预置站位与开工（需求4）**：阵前（基地/炮位 10 格内）没有活着的机器人就算"清空"，并用**连续回合去抖的夜战状态锁**决定模式——连续 2 回合清空才切到「开工」，连续 2 回合有敌才切回「防守」；单回合的翻转不改变当前模式（机器人在威胁半径边缘来回时，此前会每回合把工人从"出工"翻成"回塔"，且切换那一回合两头都不下指令，表现为在矿与塔之间踱步、既采不到矿也不防守）；模式切回防守时在炮位分配之前解除"已占岗位"，本回合即可召回，不留空转回合；另外加了**夜间兜底**：进入开工状态但这一回合拿不到任何指令的人（矿点被同伴占满 / 背包满 / 任务点没有报价）会被送回武器塔旁，不会带着"已占岗位"标记在外面干等一整夜；工人直接前往次日矿点开工采矿（夜间工人只由经济模块的 job 规划一次，避免与「预置站位」两套规划互相推翻、在矿周围来回走却不采集）、开拓者前往任务点或继续推进已有任务（官方动作 `collect/acceptTask/submitAnswer/executeCmd` 均无昼夜限制）；夜间预算按"一个完整白天"发放，避免夜/昼两套规划在清晨互相推翻；已开工角色按"已占下一天岗位"记账，不再被炮位分配拉回；机器人一旦重新靠近，下一回合判定翻回"战斗中"，离岗角色会被炮位分配召回；目的地附近仍有机器人则不冒险，已在途的角色不会被炮位分配拉回，新的一天重置。两名工人各自认领不同矿点。
- **石头只做建材（需求5）**：石头永不进出售清单（只卖铁/铜），全部留给建墙；石料需求按待建格计算。
- **采集时段（用户最新口径）**：**石头只在当天早上（前 40 回合）专门安排采集**，其余白天时间采矿赚钱（建墙缺料时仍由建墙逻辑即时补采）；**夜晚一律采矿（铁/铜）不采石**。实测 5 天对局：白天采集 铜49/铁10/石12，夜间只有 铜60/铁26。
- **第3天加长围墙（需求5）**：第3天白天把迎敌半圈沿弧线两端各加一格，10 格 → 12 格（新增格仍是环上格，已在 `wall_sites(turn, extend=1)` 与单元测试中固定）。
- **第3天围墙维护（需求5，已取消「拆掉重建」）**：不再对任何一级墙执行 `remove` + `build`（整套拆除/重建逻辑已删除，实测对局记录里 `remove` 次数为 0）；带伤的一级墙交给**围墙升级券**（升级同时回满血）；**掉血超过 50%** 的 2/3 级墙用 `WallFixer` 修复包，掉血不到一半的墙不处理。
- **基地兜底（需求3，最高优先级）**：第 3 天起只要基地受过伤（血量低于当前等级上限，含此前夜晚的擦伤），**当天第一优先级就是买基地升级券**——白天第一件事去买，夜晚回到基地旁再使用（`held_options` 的相邻使用路径）。档位按「当天白天开始时的金币」判定：已到 2 级且金币 >150 → 买 `StationUpgradeVoucher2`；否则买**当前等级**对应的券（1 级买券1、2 级买券2，不会买用不上的低档券）。
- **待建围墙格不停人（需求1）**：仍需建造的迎敌半圈围墙格与计划炮位被排除出寻路图（既不停留也不穿行），避免人物站在那一圈占位导致围墙/炮位建不起来；回归对局里前 3 天「待建格被占」从 5 次降到 0 次。
- **开拓者商店待命（需求2）**：没有任务可做时不再回基地空转，而是去最近的商店旁待命并按既定计划买券（武器券优先，与工人共用库存与配额；武器还没满级且买不起武器券时不把金币花在围墙券/修复包上）；硬性前提是「白天结束（第 70 回合）前回到武器塔旁」：去商店 + 购买 + 返程（按实际寻路，含绕开待建围墙格）+ 1 回合余量必须装得进当天剩余回合，装不下就立刻交回炮位分配送回武器塔。此前判据用的是算到第 75 回合的工人死线、且返程距离没算围墙格绕行，实测开拓者会站到第 62-63 回合才往回走、夜里第 8-10 回合才归位；现在第 70 回合已在塔旁。
- **可复用技能库**：同类任务复用已保存的 SOP——题干按"数字→#、参数→占位"归一化比对；命中后把命令里的旧参数替换为新参数重跑（参数相同则直接提交已验证答案，参数不同则用新结果请 LLM 作答，绝不沿用旧答案），省掉 3 轮探测；实测 4 天 8 次接任务 8 次完成。
- **已有升级券优先送达**：白天工人与空闲开拓者均可配送背包券，活动任务不被打断。夜间优先保证炮位，不再长途送券；仅在无有效开火方案或冷却时原地使用相邻建筑的物品。目标不可达或持续受阻时暂缓该目标 8 回合并尝试其他建筑，无合法目标时保留物品。
- **修复包储备按需定量**：储备目标 = min(3, max(2, 当前受损墙数))，避免墙壁完好时白占金币。
- **围墙按朝向排序**：围墙券优先投给最朝向机器人的墙体（迎敌弧线由前到后排序，非迎敌半圈的墙排最后），受损墙再略微提前。
- **前期金币优先武器升级**（issue #3）：取消"首日金钱>100 就买大机器人召唤令"的逻辑；武器升级候选优先于围墙升级；日配额控制采购数量和维修储备条件。召唤令只有在进入第 3 天、武器全部 ≥2 级、迎敌半圈围墙阶段完成后，才用富余金币采购。
- **围墙修复**：迎敌半圈低于 70% 血量、其他墙低于 50% 时生成已有修复包的使用候选；同一建筑只分配一名配送者。已有升级券可同时升级并回满血，不再被另一个角色的修复包遮住。修复需要实际走到交互位置，不承诺检测当回合即完成。
- **修复包储备**：当天升级配额满足后再用剩余金币采购；没有可升级武器时，武器配额视为完成，避免满级后的每日重置阻挡储备。储备目标为 2-3 个。采购与实际下单均校验背包空间和总价，已有修复包留待受损时使用。
- **回程顺手采矿**：白天返程窗口（约第 60 回合起）里，只要矿点是"家附近（≤4 格）"或相对返程路线"只多绕 ≤2 回合"，就在回家路上顺手采一两次；每回合都重新校验"采集 + 回位 + 2 回合缓冲"是否仍在白昼剩余回合内，主保证始终是入夜前回到武器旁。
- 已持有升级券时优先送达，贴着目标时即使临近天黑也使用；确认目标等级变化后解除计划。支持Weapon/Station/Wall两级券，三级残血墙支持WallFixer。
- 采矿枚举真实采集邻格、小贩邻格和采集数量，计算“当前位置→矿点→小贩→回防”的障碍路径与操作回合；采矿与立即出售统一按预计出售金币/出售并回防的总回合评分，同时约束返程期限。售价使用实时vendorShopList，支持非整数价格。
- 出售批量不再固定为6份或40金币；比较立即出售与继续采集，达到下一次升级资金门槛时可提前出售。
- 记录己方已采数量和同回合分配，减少工人争抢；矿点消失、价格变化、采集失败会触发重规划。失败矿点暂停8回合，有可靠停采消息则按日期跳过。
- 下一步路径包含当前可见移动障碍和本回合位置预留；未来行程的静态距离场不把己方角色永久当墙，实际碰撞仍会重规划。

## 移动和物品执行恢复

- 已有物品的候选独立于商店采购排序：检查物品等级、目标存活与可达性；满级或无匹配目标时不盲目消耗。无采购差事的已有大机器人召唤令也会使用；生命值低于 100 时，空闲角色白天或行走期间也可使用已有药品。
- 炮位分配先最大化可达角色/武器的匹配数量，再优先保持已就位的操作者；炮位切换增加 3 步等价成本。建造目标与交互站位尽量延续，已经到达合法位置时直接操作。夜间不因配送离岗，空闲时原地维护同一建筑最多安排一人。
- 连续 3 次移动没有位移，或出现 A→B→A→B→A 循环，暂停原站位 8 回合；清除相关建造/炮位安排，升级配送同时暂停原建筑。移动发出前再次检查建筑、角色和本回合预留格，交互函数不会把未发出的移动当成成功。
- 建造前检查基地附近到外部的连通性，避免封住角色出口，并为现有及本回合规划的武器保留互不重叠、外部可达的操炮位置。
- 采购券数量受匹配等级建筑数、已有库存、背包空位和当前金币限制；真正下单时再次计算。每日升级配额依据下一回合观察到的等级增长，移动、失败使用和单纯修墙不计入升级次数。
- 回归测试包含连续回合的开拓者送券、券消耗确认、失败重试与往返循环，以及物品保留、批量下单和建墙封路场景。测试不替代官方判题器对动态机器人碰撞和夜间战斗收益的验证。

## 独立火力控制

`fire_control.py` 输入本回合世界状态与已就位炮台，输出每座炮的落点；不修改采购、角色位置或跨回合记忆。

- **索敌**：`targetTeam` 明确时只选择攻击己方阵营的机器人。字段缺失时比较与双方基地占地的距离；看不到敌方基地时使用左右镜像位置。基地同高度的威胁是软偏好，明确攻击己方的侧后方机器人仍会被处理。对手那一波不贡献收益，溅射到它们的伤害在同收益方案中被惩罚。
- **联合规划**：最多三炮，枚举最多 6 种规划顺序；每座多弹武器保留最多 8 个候选方案，所有炮共享预计剩余血量。先最大化己方波次有效伤害，同收益时依次减少对手波次伤害与溢出，再比较威胁权重和击杀。该搜索有界，不宣称求得所有布局的全局最优解。
- **同时结算**：弹道依据回合开始时的机器人和血量计算。预计被其他炮击杀的机器人仍会阻挡加特林，并消耗电磁炮能量；预计剩余血量只用于计算有效伤害。所有发射位置均计入预估，保持武器等级对应的目标数量及加特林 90° 限制。
- **值守**：夜间存活且有可达炮位的角色先就位；有效开火优先于物品。冷却、没有己方目标，或其他炮已覆盖全部有效伤害时保持位置，不为凑齐三炮指令浪费一次齐射。

验证：相对 `e05e827`，固定随机种子 `20260913` 的 40 个合成场景中，己方波次有效伤害从 5690 提升至 6180（约 +8.6%），对手波次伤害从 140 降至 0，溢出伤害从 310 降至 280。25 个场景有效伤害提高，15 个持平。可运行 `python -B Demo/CoreGeek/tests/benchmark_fire_control.py` 复现；这些是静态场景指标，不代表官方对局胜率。

## 文件结构

- brain.py：建造、防守、全局调度。
- fire_control.py：独立索敌、弹道预测及多炮伤害分配。
- tasks.py：通用任务、新闻/宝藏、LLM协议。
- economy.py：持续采购、升级和采矿出售行程。
- geography.py / grid.py：未来行程距离场和即时路径。
- memory.py / runtime.py：跨回合状态、重复请求幂等、按队伍隔离及异常事务保护。
- server.py：完整HTTP响应。

### 本轮补充修复（夜间"在外面不回来"）

- 崩溃根因：当 `phaseTask` 有内容但 `playerTasks` 里查不到该任务点时，任务会以**空 `positions`** 建档，随后"任务点回位"里的 `min([])` 抛 `ValueError`；服务器兜底返回空指令，于是**该回合所有角色原地不动**，人一直在外面不回来。现在建档时用"己方所有任务点格"兜底，并对空列表做了防御（新增两项回归：空 positions 不崩且开拓者回塔、工人无活可干也回塔）。

## 验证边界

测试使用伪造LLM回包验证多种任务的完整协议，不代表真实模型对任意题目的正确率；未运行官方判题器，也不保证全局最优收益或首夜存活率。

接口未给出矿点剩余量，其他角色采集和未来刷新未知，采集数量只是基于己方观测的估计。当前枚举一次采集—出售行程，未求解任意多矿点组合的全局规划。

模拟平台的基地占地仍存在y+1与接口y-1差异，本次未修改。电磁弹道边界和同时伤害仍需官方判题器核对。相同队伍重新开局依靠回合回退重置状态；接口没有matchId，完全相同的重复第1回合请求会作为重试处理。
